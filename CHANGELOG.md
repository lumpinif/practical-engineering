# Changelog

This file records meaningful changes to the skill's behavior. Routine wording
and maintenance details belong in Git history.

## [Unreleased]

### Added

- Added a permission-aware GitHub feedback path for concrete cases where the
  skill misses a practical outcome or allows unnecessary process and
  complexity.

### Changed

- Made simplicity measurable through retired concepts and obligations rather
  than line or file count.
- Assigned discoverable facts to the agent and moved necessary human decisions
  behind safe preparation and evidence.
- Added symptom-specific debugging loops, confidence-aware prioritization, and
  an explicit valid no-change outcome.
- Added the deletion test while preserving distinct ownership, lifecycle, and
  failure-window guarantees.
- Strengthened behavioral tests with honest seams and independent expected
  outcomes, and separated narrow checks from broader validation claims.
- Added reasonable user expectations as a correctness criterion, with a
  proportional bar for intentionally departing from established conventions.
- Split review judgment among requested-outcome correctness, user-expectation
  fit, and implementation or contract quality.
- Required validation evidence to match the user's relevant starting condition
  when existing credentials, data, configuration, caches, or running processes
  could hide first-use or cold-start failures.
- Clarified that a real late finding does not automatically expand the current
  task, while preserving coherent root-cause and material-risk exceptions.
- Added a bounded upstream update check when the skill itself is under
  discussion or appears to have behaved poorly, without delaying unrelated work
  or changing installed skills without permission.

## [0.1.0] - 2026-08-31

### Added

- Initial outcome-first engineering guidance.
- Root-cause and ownership-based diagnosis.
- A concrete-value gate for new state, abstractions, fallbacks, layers, test
  matrices, and process.
- Risk-proportional validation and evidence-based closeout.
- Explicit boundaries against project-rule duplication, permission expansion,
  and fixed ceremony.
